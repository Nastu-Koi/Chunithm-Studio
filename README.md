# Chuni Studio

Windows 64 位 CHUNITHM 制谱器与自动播放预览。俯视编辑和透视播放位于两个独立页面，共用谱面、播放位置和音频时钟。界面为中文。

当前提供普通谱面和 WORLD’S END 的编辑、原生 C2S 读写及完整 OPT 导出。已在 Windows 桌面环境验证程序运行、原曲解码和独立追加包生成；**原游戏内的加载与视觉一致性尚待实机验收**。旧版 `STP` 的预览按区间停滚近似，原记录会保留。

0.1.10 修复 SLC 控制段重复贴图导致的紫色分隔：控制点连续通过，SLD 仍显示普通节点横条。俯视编辑器与音符工具按钮使用复制的 Margrete 1.8.0 `note_icons.png`，长条带体和编辑辅助标记仍由本程序绘制。

## 启动

解压 Windows 便携包，双击 `ChuniStudio.exe`。保留同目录的 `resources`、DLL 等文件。无需另外安装 Node.js、.NET 或 FFmpeg。

“本地曲库”的默认目录为 `D:\chunithm`。点击“扫描曲库”后可搜索曲名、ID、难度和资源包；载入后另存为工程。扫描包含基础资源和追加包，并按资源优先级继承谱面、封面和音乐。

## 播放资源副本

0.1.2 将本机游戏中的贴图和打击音转换、复制到项目 `assets/game`，便携程序中对应 `resources/app/assets/game`。0.1.9 包含 269 张去重 PNG 和 8 个 WAV，HUD 补全后为 274 张；播放器只读取这些副本，不依赖原游戏文件。播放页的“原版资源副本”按钮显示装载情况与兼容性说明。它们是程序的公共资源，无需在每个谱面工程中重复保存。

0.1.8 使用原始三维网格、UV、顶点颜色和材质绘制音符：包括 TAP、EX、FLICK、DAMAGE、HOLD／SLIDE 及其专用末节点、六种 AIR 方向、AIR HOLD／SLIDE 的动作环与阴影、CRUSH 首横档和后续横档。资源副本包含 407 个模型、711 个材质批次；AIR 长条和 CRUSH 连线按已核查的原程序规则生成。打击效果改为读取原动画帧、粒子参数和寿命，移除了旧的手绘渐变与圆环。

AIR HOLD 顶面使用原运行时透明度。AIR SLIDE 纹理跨控制节点连续，按音乐时间适应分段 BPM。CRUSH 连线支持原色带及 `DEF / AxisY / AxisZ / Trace` 四种形态；Trace 几何已与隔离的原函数输出核对。这些验证覆盖已实现的规则，仍不等于实机画面完全一致。

资源来源与完整演出是两件事：仍有部分特效命令、模型动画和实机时间基准未复现，详见 `docs/native-note-assets.md` 与 `docs/native-effects.md`，播放页“原版资源副本”也显示当前兼容性说明。默认 TAP、EX、FLICK、HOLD、SLIDE、AIR 上举／下压、AIR-HOLD 使用复制的打击音；AIR-CRUSH 音效与 CRI 动态混音仍未完整还原。曲库导入与 OPT 导出需选择游戏目录。

## 界面、舞台动作与计分

编辑页按 Margrete 官方 UI 文档调整为紧凑双工具栏、黑色谱面、细灰网格与红色光标。左侧新增独立 AIR 高度窗，拖动 AIR SLIDE / AIR CRUSH 的高度节点会同步连接处两段高度；右侧属性面板继续支持精确数值、小节与任意分音。轨道宽度 100% 为标准宽度（每轨 30 px），支持 50%–300% 调整，超出画布时可横向移动视野，“标准”恢复 100%；设置自动保存，不改变谱面轨道坐标。

0.1.10 之后（尚未打包）对照 Margrete 说明书补了编辑功能：橡皮擦工具、前后翻转、按比例缩放时间间隔、把直线 SLIDE 换成曲线、拖动左边缘改宽度、左右镜像粘贴，以及在谱面右侧显示 BPM、拍号和滚速数值；默认按键改为与 Margrete 一致。HOLD / SLIDE 的带体改用游戏贴图绘制（青 / 黄色、两端粉紫渐变，带中心线），不再是半透明色块。逐项对照与仍未实现的功能见 `docs/margrete-reference.md`。

播放页保持独立，使用固定 1920×1080 设计画幅等比缩放。顶部中央显示分数与 COMBO，右上显示当前封面、曲名、作者、难度和等级；曲目信息框、数字、TRACK 编号、WORLD’S END 星级和 COMBO 字样来自游戏资源副本。HUD 的位置与裁剪来自原 SRD 文件；轨道地面和判定线由世嘉官方游玩截图标定。

0.1.10 之后（尚未打包）的 HUD 按原游戏布局补全：中央使用原判定条、默认 Frame（含 MAX COMBO / SCORE 字样）、gauge 与 stock 方块，分数带千位逗号；左上按原玩家信息布局绘制默认名牌、称号条、`Lv.` 与 RATING；右上的流速与镜像设置使用原数字和 `OFF` 贴图。新增贴图的裁剪与位置按 SRD 节点名解析。预览没有玩家档案和技能：等级与 RATING 显示原布局自带的隐藏值，gauge 按已判定比例填充，stock 方块保持空槽，游玩画面内不再显示编辑器自绘的 AUTO JC、SPEED 与 PAUSE 文字。详见 `docs/game-scene-assets.md`。

0.1.9 的播放背景为纯黑，停用经典舞台绘制与动作控制。轨道、侧边材质与判定线仍使用项目内的原始资源。舞台解析代码和研究记录保留，当前播放页不执行舞台动画。

游玩 HUD 使用复制的原游戏 RFZ 位图字体（7,161 个字形）以及专用 COMBO 数字图集。顶部四种判定等距排列；右侧流速与反转值居中；等级以 `15` / `15+` 显示，工程内的小数值不改写。游玩画面不显示校准和统计对照文字；详细兼容性信息可在资源和统计窗口查看。

HOLD / SLIDE 地面长条改用原生加法混合，并先于音符头绘制，避免多长条互相覆盖及远处音符头被长条遮挡。保留原始纵向 UV，不凭截图旋转材质。多个长条交叉、变 BPM 与实际 GPU 混合均有回归测试。原程序的全部材质动画与特效时序仍未完全复现，不能将使用原生资源等同于逐像素还原。

## 从音乐开始制谱

1. 新建工程，在“乐曲设置”填写曲名、作者、初始 BPM、难度和封面。导入音乐后显示真实波形。
2. 选择 TAP、EX、FLICK、HOLD、SLIDE、AIR、AIR-HOLD、AIR-SLIDE、AIR-CRUSH 或 DAMAGE 工具，在轨道中点击或拖动。
3. 用选择工具移动音符、拖动宽度与长条端点。属性面板可精确编辑位置、时长、AIR 高度、原生颜色和方向；长条支持连接节点与分割。
4. 按 Tab 切换播放页，空格播放/暂停。可以拖动定位、减速和设置片段循环。播放器按判定时间表显示自动 JC 分数与 COMBO；尚未确认的规则明确标为估算。
5. Ctrl+S 保存。工程由 `.chuni.json` 和同名 `.assets` 文件夹组成；移动工程时一起复制。再次保存会保留上一版 `.bak`，未保存修改也会自动暂存并在下次启动时提示恢复。

小节线左侧显示“第 001 小节”等编号，随拍号变化计算。点击底部“小节定位”（Ctrl+G），输入小节号，可选择“定位到此”或“从此播放”；后者会切换到播放页，从该小节起点开始。编号与编辑器保持一致，支持变 BPM、3/4、7/8 等拍号。WORLD’S END 隐藏小节线的区间不额外编造小节号。

底部“速度”支持 0.25、0.5、0.75、1、1.25、1.5、2 倍，音乐与谱面同时变速，播放中可以直接切换。“轨道流速”单独控制音符画面的远近，不改变音乐速度。

选中 SLIDE、AIR HOLD 或 AIR SLIDE 后，可在属性面板选择**段末节点类型**。SLIDE 的普通／控制节点分别写为 `SLD/SLC`（EX 为 `SXD/SXC`）；AIR HOLD 的动作／无动作节点为 `AHD/AHX`；AIR SLIDE 为 `ASD/ASC`。工具栏的节点选项用于新建、接续和插入：插入类型作用于新分割点，原终点类型保留在后半段。控制点仍保留长条路径；编辑器显示控制标记，播放页按节点类型显示。核查依据与原版实机校准范围见 `docs/node-semantics.md`。

原生高度 1 是地面，5 是普通空中平面。新建 AIR SLIDE／AIR CRUSH 默认高度为 5，已有工程和导入谱面的数值保持原样。

## XML 乐曲信息

点击顶部“XML 信息”，可修改曲名、作者、谱师、排序名、发布日期、优先级、禁用／初始锁定／礼物标记，以及分类、版本登记、开放批次、作品、版权标签和舞台引用。引用的 ID 与名称应对应游戏库已有条目；发布日期使用 `YYYYMMDD`，也接受原生未设置值 `0`。留空引用保留原曲值或导出模板，舞台留空随难度设置，排序名留空使用当前曲名。

这里也可修改 Music ID 和 CueFile ID；两者可以不同。界面会预览目录与音频引用，导出时同步生成 Music.xml、CueFile.xml、ACB/AWB 文件名及相关登记。难度、等级、WORLD’S END 属性和试听时间在“乐曲设置”调整。

XML 设置随工程保存并支持撤销。从“本地曲库”载入曲目时，同时保留生效的 Music.xml 和 CueFile.xml 中未识别的字段与属性；导出会更新当前工程的身份、谱面路径、谱师与 BPM。旧工程自动获得默认设置。只有 C2S 的独立导入不会猜测配套 XML。

## 分段 BPM、拍号和非常规节奏

在目标位置放置光标，再用事件工具添加 BPM；每条 BPM 从该位置生效，音频、波形定位、预览和打击时机使用同一条分段时间轴。拍号事件改变小节线。停止和反向应使用滚速事件，不把 BPM 设为零。

量化栏允许自定义分母，例如 `4`、`7`、`11`、`16`。分母为 `0` 时自由放置；属性中的位置和时长也支持分数输入。

| 量化基准 | 分母 7 的含义 |
| --- | --- |
| 全音符 | 一个全音符等分为 7 份，每格为 `1/7` 全音符 |
| 四分拍 | 一拍等分为 7 份，每格为 `1/7` 四分拍，即 `1/28` 全音符 |

工程以分数 tick 保留这些位置。原生 C2S 使用整数 tick，默认每全音符 384 tick；`384/7` 无法原样写成整数。导出前会显示受影响对象、最大时间误差，以及 AIR-CRUSH 判定点数量是否变化。必须勾选接受对齐后才导出，**工程中的原始节奏不变**。

## WORLD’S END

在乐曲设置选择 WORLD’S END，并填写游戏已有的属性与 1–5 星。支持 DAMAGE、AIR 系列、全局滚速 `SFL`、逐音符速度 `DCM`、分组滚速 `SLP` 和关联 `SLA`。`SFL=0` 为停止，负值用于逆向滚动；`DCM` 不接受零。

“高级”中的“允许轨道外演出”可显式开放越界视觉坐标。常规模式仍使用 16 轨。开启后可编辑原生 0 基位置 `−64…64`、宽度 `1…128`，横向视野可调整或适合全部音符；导入有越界音符的原谱会自动开启。关闭开关不会改写原有音符。

未编辑的 C2S 保持原始文本；修改已知字段时保留额外列和未知记录，未知行为会提示。全库读写一致不代表每种特殊演出都已和游戏画面对照。

## 导出到原游戏

“导出 OPT”需要音乐、封面和本地游戏资源。选择一个游戏目录以外的输出目录，使用未被占用的 OPT、Music、Cue ID。默认 `AZ01 / 7000 / 7000`；导出前会检查冲突。

导出会生成原生 C2S、ACB/AWB 音乐及试听、DDS 封面、Music/Cue XML、保留现有 ID 的曲目排序表，以及 WE/ULTIMA 的开放事件。输出根目录旁置 `<OPT>-安装说明.txt`。程序不会直接安装到游戏。

以该说明为准，把新追加包安装到对应 option 目录并实机检查。检查选曲登记、封面、试听、完整音乐同步、BPM 边界、停止/逆向/超车、AIR 和 WE 星级。不要覆盖已有同名追加包。

`examples` 中的原创校准工程和七等分工程用于复现这些检查；校准包的素材由脚本合成，示例没有包含原游戏歌曲。七等分工程没有预先量化导出。

## 开发与验证

源码入口：`src/core` 为谱面、时间与量化模型，`src/renderer` 为编辑和预览，`src/backend` 为桌面文件、游戏资源和导出，`native` 为音频助手。编辑器的纯谱面变换在 `src/renderer/editor-operations.ts`，工具栏与画布标记在 `src/renderer/editor-template.ts`，`editor.ts` 只保留交互与绘制。

桌面程序通过自定义协议 `chuni-asset://game/…` 直接提供 `assets/game` 中的贴图，主进程只把清单和 URL 交给渲染进程，不再把 PNG 转成 base64 经 IPC 传递；该协议只响应资源目录内的 PNG / WAV / JSON，并带 CORS 头以供 WebGL 读取。`.github/workflows/ci.yml` 在推送时运行类型检查、单元测试和渲染端构建。

```sh
npm ci
npm run build
npm run desktop
npm test
```

音频助手的构建和许可见 `native/README.md`。`native/win-x64`（ffmpeg 与 .NET 自包含助手，约 155 MB）不进入仓库，由 `npm run prepare:native` 从固定版本的上游下载并发布，需要网络和 .NET SDK；`npm run package:win` 会先执行它。打包还需要匹配 sharp 版本的 Windows 包，准备步骤见 `scripts/package-win.mjs`。

浏览器仅用于开发 UI，完整曲库和 OPT 功能应在桌面程序中使用。`npm run dev` 后可用 Playwright 执行 `tests/player.e2e.mjs`、`tests/rhythm.e2e.mjs`。设置 `CHUNI_UI_URL` 会启用编辑器交互测试；设置 `CHUNI_GAME_ROOT` 会启用全库原生往返测试。`scripts/copy-game-resources.ts` 是一次性资源复制脚本；运行中的程序从 `assets/game` 读取预览素材。
