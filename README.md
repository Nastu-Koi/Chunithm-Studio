# Chuni Studio

Windows 64 位 CHUNITHM 制谱器与自动播放预览。俯视编辑和透视播放位于两个独立页面，共用谱面、播放位置和音频时钟。界面为中文。

当前提供普通谱面和 WORLD’S END 的编辑、原生 C2S 读写及完整 OPT 导出。已在 Windows 桌面环境验证程序运行、原曲解码和独立追加包生成；**原游戏内的加载与视觉一致性尚待实机验收**。旧版 `STP` 的预览按区间停滚近似，原记录会保留。

## 启动

解压 Windows 便携包，双击 `ChuniStudio.exe`。保留同目录的 `resources`、DLL 等文件。无需另外安装 Node.js、.NET 或 FFmpeg。

“本地曲库”的默认目录为 `D:\chunithm`。点击“扫描曲库”后可搜索曲名、ID、难度和资源包；载入后另存为工程。扫描包含基础资源和追加包，并按资源优先级继承谱面、封面和音乐。

## 播放资源副本

播放页使用随程序分发的资源副本：从原游戏转换的贴图、模型和打击音，位于便携程序的 `resources/app/assets/game`。播放器只读取这些副本，不依赖原游戏文件。它们是程序的公共资源，无需在每个谱面工程中重复保存。播放页的“原版资源副本”按钮显示装载情况与兼容性说明。

音符、AIR、CRUSH 与打击效果按原始模型、材质和动画数据绘制。使用原始资源不等于完整演出：仍有部分特效命令、模型动画和实机时间基准未复现，已验证的规则也不代表实机画面完全一致，详见 `docs/native-note-assets.md` 与 `docs/native-effects.md`。默认 TAP、EX、FLICK、HOLD、SLIDE、AIR 上举／下压、AIR-HOLD 使用复制的打击音；AIR-CRUSH 音效与 CRI 动态混音仍未完整还原。曲库导入与 OPT 导出需选择游戏目录。

## 界面、舞台动作与计分

编辑页按 Margrete 官方 UI 文档调整为紧凑双工具栏、黑色谱面、细灰网格与红色光标。左侧有独立的 AIR 高度窗，拖动 AIR SLIDE / AIR CRUSH 的高度节点会同步连接处两段高度；右侧属性面板支持精确数值、小节与任意分音。轨道宽度 100% 为标准宽度（每轨 30 px），支持 50%–300% 调整，超出画布时可横向移动视野，“标准”恢复 100%；设置自动保存，不改变谱面轨道坐标。

编辑功能参照 Margrete 说明书：橡皮擦工具、前后翻转、把直线 SLIDE 换成曲线、拖动左边缘改宽度、左右镜像粘贴，以及在谱面右侧显示 BPM、拍号和滚速数值；默认按键与 Margrete 一致。逐项对照与仍未实现的功能见 `docs/margrete-reference.md`。

播放页保持独立，使用固定 1920×1080 设计画幅等比缩放。顶部中央显示分数与 COMBO，右上显示当前封面、曲名、作者、难度和等级，左上显示默认名牌、称号条、等级与 RATING。播放背景为纯黑，不执行舞台动画。

预览没有玩家档案和技能：等级与 RATING 显示原布局自带的隐藏值，gauge 按已判定比例填充，stock 方块保持空槽。等级以 `15` / `15+` 显示，工程内的小数值不改写。游玩画面不显示校准和统计对照文字；详细兼容性信息可在资源和统计窗口查看。HUD 的资源来源与布局见 `docs/game-scene-assets.md`。

## 从音乐开始制谱

1. 新建工程，在“乐曲设置”填写曲名、作者、初始 BPM、难度和封面。导入音乐后显示真实波形。
   对齐音乐：把光标放到目标小节线（想在开头留一小节空白就放在第 2 小节线），点击工具栏“♫ 对齐音乐”，在加宽的高精度波形上点击那一拍的起音，程序会改写音乐偏移，使该起音落在光标上；Ctrl+滚轮可放大到约 0.25 ms/像素，±1 / ±10 ms 按钮用于微调，Esc 退出，整个过程可撤销。打开底部“节拍器”后播放，可以听拍点与音乐是否重合。对齐只移动音乐，不移动音符。
2. 选择 TAP、EX、FLICK、HOLD、SLIDE、AIR、AIR-HOLD、AIR-SLIDE、AIR-CRUSH 或 DAMAGE 工具，在轨道中点击或拖动。
3. 用选择工具移动音符、拖动宽度与长条端点。属性面板可精确编辑位置、时长、AIR 高度、原生颜色和方向；长条支持连接节点与分割。
4. 按 Tab 切换播放页，空格播放/暂停。可以拖动定位、减速和设置片段循环。播放器按判定时间表显示自动 JC 分数与 COMBO；尚未确认的规则明确标为估算。
5. Ctrl+S 保存。第一次保存（或 Ctrl+Shift+S 另存为）时选择一个位置，程序在其中新建以曲名命名的**项目文件夹**，内含 `project.chuni.json`、`audio.<扩展名>` 和 `cover.<扩展名>`；已有同名文件夹时不会覆盖。导入的音乐和封面在保存时才复制进文件夹，被替换的旧素材同时删除，所以文件夹始终与上一次保存一致，移动或备份时复制整个文件夹即可。再次保存会保留上一版 `project.chuni.json.bak`，未保存修改也会自动暂存并在下次启动时提示恢复。
6. “打开”列出最近 10 个项目，也可以“浏览文件夹…”选择任意项目文件夹。音乐或封面文件丢失时项目照常打开，并提示重新导入。旧版的 `.chuni.json` + `.assets` 工程不再支持。

音乐偏移在导出后保持一致：编辑器试听用的压缩音频（mp3、ogg、flac、m4a、aac）与导出使用同一次 FFmpeg 解码，偏移在重采样到 48 kHz 之后按整数采样点补静音或裁剪，再编码为 HCA。游戏内的判定与音频延迟设置不在工程范围内。

小节线左侧显示“第 001 小节”等编号，随拍号变化计算。点击底部“小节定位”（Ctrl+G），输入小节号，可选择“定位到此”或“从此播放”；后者会切换到播放页，从该小节起点开始。编号与编辑器保持一致，支持变 BPM、3/4、7/8 等拍号。WORLD’S END 隐藏小节线的区间不额外编造小节号。

底部“速度”预设 0.1、0.25、0.5、0.75、1、1.25、1.5、2 倍，下拉里选“自定义…”可输入 0.10–2.00 之间的任意倍率，两侧的 −／+ 在预设档位之间切换（从自定义值出发也按就近的预设走）；音乐与谱面同时变速，播放中可以直接切换，选择与自定义值都会记住。“轨道流速”与原游戏的 SPEED 选项档位相同（1.00–15.00 每档 0.25，之后 16–19），只改变音符移动的快慢，不改变音乐速度；“挡板”对应原游戏的 FIELD WALL（0–16），从远端遮住轨道，使用原游戏的默认挡板贴图。数值来源与未核对的部分见 `docs/native-scroll-speed.md`。

音量、打击音与节拍器开关、播放速度、轨道流速、挡板、当前所在的页面，以及编辑页的音符间隔、缩放、新音符宽度和 SLIDE 控制（新节点类型）会记在本机，下次打开时沿用。

SLIDE、AIR HOLD 与 AIR SLIDE 按**节点**编辑：点在节点上选中该节点，属性面板显示它的类型、位置、轨道、宽度（AIR SLIDE 另有高度），修改时前后两段一起跟随；点带体选中的是一段，面板里没有节点类型。删除也按节点：右键（或橡皮擦）点头节点删除整条长条，点其他节点只删该节点并把前后两段接上，点最后一个节点去掉最后一段；带体不能单独删除。SLIDE 的普通／控制节点分别写为 `SLD/SLC`（EX 为 `SXD/SXC`）；AIR HOLD 的动作／无动作节点为 `AHD/AHX`；AIR SLIDE 为 `ASD/ASC`。工具栏的节点选项用于新建、接续和插入：插入类型作用于新分割点，原终点类型保留在后半段。控制点仍保留长条路径；编辑器显示控制标记，播放页按节点类型显示。核查依据与原版实机校准范围见 `docs/node-semantics.md`。

多个音符或节点叠放在同一位置时，在原处再次单击会依次选中下面的一个，提示栏显示“叠放 2/3”这样的位置。把 ExTAP 拖到 HOLD / SLIDE 的头上（时间、轨道和宽度都重合）会并入长条，使它成为 EX，与直接用 ExTAP 工具点在长条头上相同。右键（或橡皮擦）点 EX 长条的头时分两步：第一次只取消 EX，第二次才删除长条。

AIR、AIR-HOLD、AIR-SLIDE 与原游戏一样绑定在地面音符上：只能放在 TAP / ExTAP / FLICK 上或 HOLD / SLIDE 的终点，每个地面音符（整条 SLIDE）带一个；位置与宽度跟随父音符，移动、复制、删除父音符时一并处理。没有父音符的 AIR 会让原游戏读谱失败，校验将其列为错误并阻止导出。依据见 `docs/native-judgement-reader.md`。

原生高度 1 是地面，5 是普通空中平面。新建 AIR SLIDE／AIR CRUSH 默认高度为 5，已有工程和导入谱面的数值保持原样。原游戏的镜头会让更高的 AIR 飘向画面顶部，高度 15 起整条轨道上都看不见；编辑页据此把 AIR SLIDE／AIR CRUSH 的带体从高度 5 到 15 逐渐变淡（最淡仍可选中），AIR 高度视图在谱面有高于 5 的 AIR 时扩到至少 15，并用红色虚线标出“实机可见上限”。播放页按同一镜头投影，高 AIR 会真的飘出画面。

## XML 乐曲信息

点击顶部“XML 信息”，可修改曲名、作者、谱师、排序名、发布日期、优先级、禁用／初始锁定／礼物标记，以及分类、版本登记、开放批次、作品、版权标签和舞台引用。引用的 ID 与名称应对应游戏库已有条目；发布日期使用 `YYYYMMDD`，也接受原生未设置值 `0`。留空引用保留原曲值或导出模板，舞台留空随难度设置，排序名留空使用当前曲名。

这里也可修改 Music ID 和 CueFile ID；两者可以不同。界面会预览目录与音频引用，导出时同步生成 Music.xml、CueFile.xml、ACB/AWB 文件名及相关登记。难度、等级、WORLD’S END 属性和试听时间在“乐曲设置”调整。

XML 设置随工程保存并支持撤销。从“本地曲库”载入曲目时，同时保留生效的 Music.xml 和 CueFile.xml 中未识别的字段与属性；导出会更新当前工程的身份、谱面路径、谱师与 BPM。旧工程自动获得默认设置。只有 C2S 的独立导入不会猜测配套 XML。

## 分段 BPM、拍号和非常规节奏

在目标位置放置光标，再用事件工具添加 BPM；每条 BPM 从该位置生效，音频、波形定位、预览和打击时机使用同一条分段时间轴。拍号事件改变小节线。停止和反向应使用滚速事件，不把 BPM 设为零。

“音符间隔”栏允许自定义分母，例如 `4`、`7`、`11`、`16`。分母为 `0` 时自由放置；属性中的位置和时长也支持分数输入。

分母总是把一个全音符等分：填 `7` 每格为 `1/7` 全音符；要把一拍分成 7 份就填 `28`。

工程以分数 tick 保留这些位置。原生 C2S 使用整数 tick，默认每全音符 384 tick；`384/7` 无法原样写成整数。导出前会显示受影响对象、最大时间误差，以及 AIR-CRUSH 判定点数量是否变化。必须勾选接受对齐后才导出，**工程中的原始节奏不变**。

## WORLD’S END

在乐曲设置选择 WORLD’S END，并填写游戏已有的属性与 1–5 星。支持 DAMAGE、AIR 系列、全局滚速 `SFL`、逐音符速度 `DCM`、分组滚速 `SLP` 和关联 `SLA`。`SFL=0` 为停止，负值用于逆向滚动；`DCM` 不接受零。

“高级”中的“允许轨道外演出”可显式开放越界视觉坐标。常规模式仍使用 16 轨。开启后可编辑原生 0 基位置 `−64…64`、宽度 `1…128`，横向视野可调整或适合全部音符；导入有越界音符的原谱会自动开启。关闭开关不会改写原有音符。

未编辑的 C2S 保持原始文本；修改已知字段时保留额外列和未知记录，未知行为会提示。全库读写一致不代表每种特殊演出都已和游戏画面对照。

## 导出到原游戏

“导出 OPT”需要音乐、封面和本地游戏资源。选择一个游戏目录以外的输出目录，使用未被占用的 OPT、Music、Cue ID。默认 `AZ01 / 7000 / 7000`；导出前会检查冲突。

导出会生成原生 C2S、ACB/AWB 音乐及试听、DDS 封面、Music/Cue XML、保留现有 ID 的曲目排序表，以及 WE/ULTIMA 的开放事件。输出根目录旁置 `<OPT>-安装说明.txt`。程序不会直接安装到游戏。

以该说明为准，把新追加包安装到对应 option 目录并实机检查。检查选曲登记、封面、试听、完整音乐同步、BPM 边界、停止/逆向/超车、AIR 和 WE 星级。不要覆盖已有同名追加包。

`examples` 中的原创校准工程和七等分工程用于复现这些检查；校准包的素材由脚本合成，示例没有包含原游戏歌曲。七等分工程没有预先量化导出。

## 导出俯视图片

导出对话框的“导出俯视图片”把当前谱面画成一张 PNG，版式仿照 sdvx.in 的谱面页：页头是封面、曲名、艺术家、难度与等级、BPM（有变化时写范围）、CHAIN（判定总数）和谱师；正文按列排小节，一列 16 拍（4/4 时 4 个小节），小节在列内自下而上、列自左而右，每行 8 列，小节号从 1 起（第 0 小节有音符时也画出）。每拍 96 像素，BPM 变化处拍距按 BPM 反比缩放，比一列长的小节单独成列并把整行拉到它的高度。

音符用资源副本里的原版贴图绘制（音符、长条端点与节点、HOLD／SLIDE 带体、AIR 箭头、AIR-HOLD／AIR-SLIDE 的顶面与中线、AIR-CRUSH 的横档与连线）；长条带体从起点起一个 12 分音符内全亮，之后变暗，便于分辨起点，所以需要程序已载入资源副本；浏览器开发预览没有资源副本，不能导出。资源副本缺少某种贴图时对应音符不画，导出后的提示会列出缺少的贴图名。

## 从源码运行

需要 Node 22（见 `.nvmrc`）。

```sh
npm ci
npm run build
npm run desktop
npm test
```

代码格式由 Prettier 统一（配置见 `.prettierrc.json`）：`npm run format` 格式化全部代码，`npm run format:check` 只检查，CI 会运行后者。

音频助手的构建和许可见 `native/README.md`。`native/win-x64`（ffmpeg 与 .NET 自包含助手，约 155 MB）不进入仓库，由 `npm run prepare:native` 从固定版本的上游下载并发布，需要网络和 .NET SDK；`npm run package:win` 会先执行它。打包还需要匹配 sharp 版本的 Windows 包，准备步骤见 `scripts/package-win.mjs`。进入包内的只有 `scripts/package-files.mjs` 列出的运行时文件（`package.json`、`dist`、`dist-electron`、`node_modules`、`assets`、`native/win-x64`），新增运行时目录时要在那里登记；整包约 600 MB。打包输出位于 `release/<版本号>/`。

浏览器仅用于开发 UI，完整曲库和 OPT 功能应在桌面程序中使用。`npm run dev` 后可用 Playwright 执行 `tests/player.e2e.mjs`、`tests/rhythm.e2e.mjs`。设置 `CHUNI_UI_URL` 会启用编辑器交互测试；设置 `CHUNI_GAME_ROOT` 会启用全库原生往返测试。

模块划分、进程边界和数据流见 `docs/architecture.md`，项目术语见 `CONTEXT.md`。
