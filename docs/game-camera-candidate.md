两个三维候选值之前存在相似的记录布局，包括值 `1` 和两次 `60`，但没有完成节点表、字段类型、指针、关键帧或父变换解析。不能据此排除它们属于动画值，亦不能证明哪一时刻生效。

文件中能读到来源名称 `PROJECT/Chuni/.../rawdata/acro_data/.../notesfield/chu_nf_gamecamera_v10.afc`；没有找到可直接将上述字段命名为 position、target 或 FOV 的 ASCII 字段名。文件名支持“与轨道相机有关”，不确定具体字段语义。当前项目的 AVTS/SVO 解析器只处理网格与材质，没有解码 AFNC 相机。

对相机、轨道、舞台三个完整 AFB 做精确字节搜索，均未找到 little-endian float32 或 float64 的 `-65`。舞台文件为 663,360 字节、首个 AVTS 在 `0x4500`，SHA-256 为 `2e793272fed57c20074965c2e8ab3dc85fd4d7f11e86f44d5a5b205bfbba97a8`。没有在这些文件中找到该字面值，**不等于证明运行时没有此平移**：它仍可能来自复合变换、编码数据或程序中的常量。本轮没有扩展到可执行文件分析。

## 条件成立时的数学投影

仅为检验候选的一致性，假定：eye=`(0,57,44)`，target=`(0,3,-146.5)`，世界上方为 +Y，垂直 FOV=`27.5°`，画面为 1920×1080，采用常规透视 look-at。此时焦距约 `2206.79786 px`；由向量导出的俯角约 `15.82615°`。这两个数都是**建立在字段解释假设上的计算结果**，不是另行解出的引擎参数。

令 `F=normalize(target-eye)`、`U=(0,-F.z,F.y)`、`V=P-eye`、`d=dot(V,F)`。投影为：

```text
f = 540 / tan(27.5° / 2)
x = 960 + f * V.x / d
y = 540 - f * dot(V,U) / d
```

| 检查点 | 候选投影，1920×1080 | 官方截图测量 |
| --- | --- | --- |
| z=0、未经平移的近端 x=±32 | x=-260.13…2180.13，y=2173.43 | 明显不在判定线位置 |
| 加入 z=-65 平移后的近端 x=±32 | x=373.54…1546.46，y=1000.24 | x≈374…1542，y≈998；读取误差约 ±6.4 px |
| 世界负 Z 方向的消失点 | `(960,-85.55)` | `(958,-88)`；读数估计误差约 ±9.6 px |
| 平移后轨道网格远端 z=-535 | x=836.67…1083.33，y=142.79 | 顶部 HUD 遮挡，不能独立认定为画面可见远端 |

官方依据来自 [SEGA 基本玩法页面](https://chunithm.sega.com/play/) 的 [06.png](https://chunithm.sega.com/assets/img/play/game/06.png)，本地原图为 [official-gameplay-tap.png](references/official-gameplay-tap.png)。具体取点、16:9 换算与误差说明见 [场景参考文档](game-scene-reference.md)。截图所属确切版本、所用舞台与本地 stage1 的对应关系仍未确认。

三个投影锚点的吻合让这一解释具有继续验证的价值，但 `-65` 是使平面近端落到判定线附近的假设，不能把拟合成功当作独立的变换证据。要升级为“原始相机已还原”，还需解码 AFNC 的字段／动画／父变换，查明真实 notesField 世界矩阵和判定线所在局部 z，再用更多时刻或原版画面对照。此次不据此替换实现中的截图标定锚点。


## 0.1.6 后续结构核对

后续已通过 AFNC 重定位和节点链验证相关向量确实处于相机记录，并区分舞台/轨道相机。原轨道近平面不等于判定线，因此不得把早先的 `−65` 校准值当作整个场景的世界平移。见 [game-camera-decoding.md](game-camera-decoding.md) 的新证据与限制；本文件保留早期候选研究记录。
