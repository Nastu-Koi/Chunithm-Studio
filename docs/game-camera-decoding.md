## 公开解析器的适用范围

找到 [hyperbx/Marathon 的 Acroarts 解析器](https://github.com/hyperbx/Marathon/tree/e7bc25e78def68075fa434989c2841021f38a6e9/Marathon/Formats/Acroarts)。其 [AckResource.cs](https://github.com/hyperbx/Marathon/blob/e7bc25e78def68075fa434989c2841021f38a6e9/Marathon/Formats/Acroarts/AckResource.cs) 固定版本 2006020901，处理 MRAB／ABDA／ABDT，并注明研究使用 Rambo 的符号。当前 CHUNITHM 文件是 FILS／FILE／AFNC、版本 2012060601，不能直接喂给该解析器。

其 [MomentumType.cs](https://github.com/hyperbx/Marathon/blob/e7bc25e78def68075fa434989c2841021f38a6e9/Marathon/Formats/Acroarts/Types/Momentums/MomentumType.cs) 虽然命名 CameraPosition／CameraTarget，但对应整数 `0x1c2/0x1c3` 在当前相机文件中均不存在。此次没有把旧枚举强套到新格式。[MotionSet.cs](https://github.com/hyperbx/Marathon/blob/e7bc25e78def68075fa434989c2841021f38a6e9/Marathon/Formats/Acroarts/Types/Momentums/MotionSet.cs) 自身还有大量 UnknownField，不能作为当前舞台动画速度、循环或选择规则的证明。

可复用且已独立验证的是 [BINARelocationTable.cs 的偏移编码](https://github.com/hyperbx/Marathon/blob/e7bc25e78def68075fa434989c2841021f38a6e9/Marathon/IO/Types/BINA/BINARelocationTable.cs)：首字节高两位决定 1／2／4 字节编码，余下 6／14／30 位表示相邻指针槽的距离，单位为 4 字节。此次用该规则准确遍历全部 567 个指针槽。相关源码副本与原 MIT LICENSE 存在 `out/camera-research/`，没有引入生产依赖。

## 本地 AFNC 确认的结构

三份文件的 AFNC 均位于 `0x60`，其头长 32；头中 payloadSize 加上头长后恰好落到 POF0 块。AFNC 中所有相对指针以 **AFNC 块起点** 为原点，不以 payload 起点为原点。每个 POF0 的头后先读 length，再读差分编码。

相机的 AFNC payloadSize=`0x1860`，POF0 位于 `0x18e0`，length 字段位于 `0x1900`，值 132；编码从 `0x1904` 开始。例：指针槽 `0x144` 的值 `0x204` 指向绝对 `0x264`。这些指针槽来自 POF0，而非把“看起来像地址”的整数全当指针。

三个 AFNC 里的根节点都由 `AFNC+0x80` 的指针槽指向 `0x104`。节点观察到以下布局；括号中的语义仍为推断：

| 节点内偏移 | 已确认内容 |
| --- | --- |
| `+0x00/+0x04/+0x08` | 类型标签样整数、ID 样整数、另一类别整数；保留原值 |
| `+0x20` | AFC 来源文件名指针 |
| `+0x24` | 三个样本中按遍历顺序连续递增的序号 |
| `+0x28` | 相机两例为 5；其他节点存在 -1／0 等 |
| `+0x3c` | 属性链首指针 |
| `+0x40/+0x44` | 状态链首指针／状态数量 |
| `+0x50/+0x54` | 两条节点边；树形关系与 child／sibling 相符，名称未获运行时确认 |
| `+0x5c` | 节点额外资料指针；部分节点可继续读出 LightAmbient 等明文名称 |

必须遍历两条节点边；只跟 `+0x50` 会漏掉舞台大多数节点。状态链每记录 32 字节：`+0` 为 ID、`+20` 为命令链指针、`+24` 为命令数、`+28` 为下一个状态。命令记录 `+0` 为种类，`+32` 为下一个命令，`+36` 为描述记录指针。

目前只把 kind=100 的共同描述结构读为 `{selector, recordCount, recordPointer}`；每条参数记录 116 字节，三维值在记录 `+52`。其余参数全部保留原始整数。模式／属性／时间字段尚未统一命名；多个记录中出现 `60`，**不能因此认定文件帧率为 60 fps**。

## 相机的 15 个状态与舞台内第二份相机

`nf_gamecamera.afb` 只有一个节点：头位于 `0x104`，第一个整数为 6000001，ID 样字段为 1000，序号 1，`+0x28=5`。设置指针指向 `0x164`，其中 `+12` 即文件 `0x170` 保存 27.5。

状态 ID 是 `0…7, 101…107`，每个状态都有两个 kind=100 命令，selector 分别为 1／2。ID=0 的三维参数正是 `(0,57,44)` 和 `(0,3,-146.5)`。其余状态仅改变 X：

JSON 保留实际 float32 值；表格仅作显示取整。这是有显式 ID 的状态结构，不能将列表顺序当成时间关键帧。左右用途及运行时选择条件未知。

舞台 AFB 的第 25 节点位于 `0x30f4`，`+0x28` 同样为 5，kind=100 的 selector 1／2 也分别包含 **完全相同的** `(0,57,44)`／`(0,3,-146.5)`。这是另一份资源里的结构与数值佐证，提高了 eye／target 解释的可信度；由于没有对应的新格式字段枚举或执行路径，本文仍将名称列作候选。

但两份相机的投影设置**并不完全相同**。舞台节点的额外设置块在 `0x3154`，对应 FOV 候选 `27.0`（`0x3160`）、裁剪候选 `10/10000`（`0x3164/0x3168`）；独立轨道相机为 `27.5`、`1/1500`。这支持舞台与轨道采用各自投影设置的解释，不能把轨道相机的全部字段无条件用于背景。是否分层渲染、如何合成，仍需运行时证据。

## 舞台模型与 10 个动画资源的关联

舞台第 13 节点 `0x10dc` 的属性链中：kind=200 的一项引用为 `{0,-1}`；kind=400 声明 10 项，数据恰好是 `{1,-1}…{10,-1}`。属性头的 `+8` 是数组指针、`+12` 是数量、`+16` 是下一个属性。结合 AFRC 资源目录可核对模型 0 与动画资源 1…10 的关联；具体资源名和 UVC 数据由舞台动画研究记录。

舞台资源核查与之对应：0 为 `st_00001_ring.svo`，1…10 依序为 `st_00001_ring_0.uvc`…`st_00001_ring_9.uvc`。各动画均声明 901 帧、47 个 sceneNode、37 个 animated transform，名字相同但曲线／默认变换不同。这证实十个资源被该节点引用，不能证明是轮播、随机选择、同时生成或按其他状态选择。

同一节点状态 ID=0 含四个命令：kind 600／106／300／751。kind=600 的记录内有 float `1,0,-1`；kind=751 的 payload 包含整数 900，与 901 帧素材的末帧编号相符。**这些只是字段数值与关联，尚不能证明速度 1、首尾帧、循环、随机选择或十片段轮播。** 命令和嵌套指针的完整偏移保留在 JSON，不据这些相似性补造原生播放规则。

## kind=106：目标变换候选，不是已确认静态平移

第 13 节点的 kind=106 命令位于 `0x12a8`，描述块在 `0x13bc`；描述块首指针指向 `0x13e4`，数量为 1。该参数记录含三维值 `(0,0,-1600)`（记录 `+0`）、整数 0（`+36`）、浮点 800（`+44`）、浮点 1（`+60`）。这是原数据，负 Z 的量级确实可能解释为何环网格的 UVC 局部坐标需经过另一层变换才能位于相机前方。

为辨别它是否静态位移，另只读对照四个相邻基础舞台：AIR、STAR、AMAZON、CRYSTAL。指针链得到 18 个 kind=106 命令、38 条记录，记录步长为 **92 字节**。产物见 [kind106-comparison.json](../out/camera-research/kind106-comparison.json)，可用 `python3 out/camera-research/compare_kind106.py` 重现。这些附加文件的节点序号有空缺，因此只沿重定位表验证节点链，未套用前三样本的序号连续假设。

AIR 舞台给出以下成对记录：

| 描述块偏移 | 记录 `+36` | 记录 1 向量／`+44` | 记录 2 向量／`+44` |
| --- | ---: | --- | --- |
| `0x168c` | 1 | `(0,0,0)`／0 | `(0,0,60)`／180 |
| `0x4478` | 0 | `(0,20,0)`／0 | `(0,0,0)`／1000 |
| `0x58f8` | 2 | `(1,1,1)`／0 | `(20,20,20)`／90 |
| `0x6758` | 2 | `(0.5,0.5,0.5)`／0 | `(1.5,1.5,1.5)`／90 |

数值组合强烈支持 `+36` 区分位移／旋转／缩放、`+44` 参与目标时间或补间时长的解释。部分第二记录另有模式样整数 3 和浮点 0.5，说明还可能涉及缓动。这是跨文件推断，**没有证明插值公式、默认起值、相对／绝对坐标、时间单位或重复模式**。

因此，不能将 yellowring 的 -1600 在每一帧无条件加到模型上并宣称为原生世界位置；它也可能是经过 800 时间单位抵达的目标。旧 2006 枚举中 decimal106 名为 ParticleBillboardND，当前 kind100 的公用变换结构又与旧枚举不一致，不能据整数相同为当前 kind106 命名。

此外，ring 的祖先链是序号 `1→2→9→10→11→12→13`。第 11 节点的 kind100 参数包括平移 Z=-3000、旋转与周期样参数，第 12 节点包括平移 Z=+3000；这种组合与旋转支点结构相符，但矩阵乘法顺序及动态量仍未证实，不能把两次平移简单抵消。原 UVC 蒙皮后的局部顶点不等于最终场景位置。

下一步若用于实现，应分开“已解出的节点层级／资源索引／曲线值”与“待确认的命令解释器／状态选择／时间单位”。目前可靠推进点是读取原始曲线和节点数据；相机矩阵、动画运行时行为及原生计分均不能由本研究的数值吻合直接推出。

## 2026-10-09：原程序静态执行路径的新证据

下列结果来自只读 `bin/chusanApp.exe` 的 PE32／MSVC RTTI、虚表与反汇编，**不再依赖旧版 Acroarts 枚举推断**。没有执行游戏。`out/camera-research/exe-rtti.json` 保存源 SHA-256；`exe_symbols.py` 可复现 RTTI 定位，`command-class-ids.json` 保存类名、虚表、返回 ID 的方法地址。所有地址是该本地二进制的 VA，版本改变后不可直接复用。

| 命令 ID | 原生 RTTI 类名 | 返回 ID 的函数 VA |
| --- | --- | --- |
| 100 | `MomMatrix` | `0x14a1bb0` |
| 106 | `MomMatrixGoal` | `0x14a43b0` |
| 300 | `MomMaterial` | `0x14b2d40` |
| 600 | `MomMotionSet` | `0x14b6c40` |
| 750 | `MomTimeRate` | `0x14b8bd0` |
| 751 | `MomChangeState` | `0x14b91e0` |

方法是从类名的 TypeDescriptor 找 CompleteObjectLocator，再找虚表，解析方法 1 的 E9 跳板；目标函数直接 `mov eax, ID; ret`。这补足上文无法确认现代命令名称的限制。

**随机动画选择已确认。** `MomMotionSet` 初始化 `0x14b63d0` 在 `0x14b6513` 读取当前 92 字节 motion record 的 `+0`。若为 -1，会获取绑定动画数量，调用 `0x126a570(count - 1)`；后者更新 PRNG 状态并对 count 求余。yellowring 记录 `0x1344` 的首字段正是 -1，所绑定十个 UVC 因此是随机选择，不是按编号轮播。记录 `+8=1.0` 写入速度参数容器；更新函数按 `frame += sampledSpeed * node[+0xd0]` 推进。`+12=0` 是起始帧，`+16=-1` 走动画总长度分支，`+20=0` 是本条 motion 的循环计数。参数容器可以覆盖文件默认值；这里只确认未覆盖的路径。证据：`motion-init.asm`、`MomMotionSet__-2.asm`、`random-clip.asm`、`clip-count.asm`。

**900 时刻是本节点的状态重建。** `MomChangeState::update`（`0x14b8e00`）对 descriptor `+4=0`，比较累计时间与阈值，再累加 node `+0xd0`。yellowring 阈值是 900，最多触发一次，动作数组一条 28 字节记录：`[2,3,0,0,0,0,0]`。dispatcher `0x148bc80` 的 type 2／scope 3 分支到 `0x12679e0(stateID=0)`，经 `0x1268920` 查找本节点状态，再到 `0x1269140` 释放旧命令并沿 state 0 命令链重新创建。相同状态没有提前跳过。因此重建会重新初始化随机选片及 Goal，不能只把 UVC 最后一帧冻结；亦不能据此推断全场所有随机调用的种子与顺序。证据：`change-state.asm`、`state-action.asm`、`state-target.asm`、`state-find.asm`、`state-switch.asm`。

**-1600 是线性目标，800 是内部时长。** `MomMatrixGoal` 初始化 `0x14a2ee0` 在记录 `+48<0` 时把 `+44` 复制到运行时 duration；本样本该值为 800。更新按 `+36` 分派位移／旋转／缩放，补间函数 `0x14a3900` 的 mode 0／easing 0 使用 elapsed / duration，到达后直接取目标。yellowring `+36=0,+40=0,+56=0`，目标向量为 `(0,0,-1600)`；第一条记录的 start=-1 可立即开始。初始矩阵、父级矩阵及更新时间仍影响最终世界位置，不能把它替换成静态平移。证据：`goal-init.asm`、`goal-interpolate.asm`、`MomMatrixGoal__-2.asm`。

**时间单位仍未证明等于秒或 60 fps。** 节点更新 `0x1267450` 从父节点 `+0xd0` 继承时间增量；某些标志还会将其加倍。`0x12af870` 是外部可设置增量的包装方法。当前尚未串起游戏的舞台调用方到该值的完整链路。900、800、UVC 901 帧共享可运算的内部时间量，但不能单靠数值推出秒率。纯重放应显式接收内部时间或用户声明的预览速率，直到来源确认。

## 父级矩阵与相机：执行路径及数值验证

`SglNull::update` 先调用 `0x1265830` 初始化当前矩阵，再调用 `0x1265ad0` 执行命令。默认继承模式在 `0x12658a9` 将父节点矩阵完整复制到当前节点；构造器 `0x1268bd8/0x1268be2` 将继承模式字段 `+0xf4/+0xf8` 初始化为 0。普通命令执行顺序是节点 `+0x48` 的公共命令、当前状态命令、节点 `+0x4c` 的后置命令；生产解析器现在同时保留这三条链。外部修改继承方式、骨骼挂接与附加矩阵另有路径，本次未模拟。

`MomMatrix` 的记录属性 0／1／2 分别进入平移／旋转／缩放分支。平移 helper 为 `0x149f7d0`，旋转 helper 为 `0x149ee70`；以列向量表示，运算是 `current * local`，同条旋转记录按 Z、Y、X 轴顺序乘入。矩阵的内存布局为 column-major 4×4。固定正弦模式 3 在 `0x149e937` 使用 float32 的 `360 / period * elapsed + phase`，转换到 16 位角，再调用 `0x126a8a0`。这不是任意平滑摆动：`stageSinCos` 按 `0x126aae0` 的八分区间、五／六阶多项式和逐级 float32 运算复现。

yellowring 的父级记录因此可按原序执行：Z=-3000 → X=3° → Y 在 ±3.5° 间以 1600 单位周期摆动 → X 在 0° 与 -1° 间以 900 单位周期摆动 → Z=+3000，最后乘入 model 的局部 Goal。两次大平移定义旋转支点，不能相互删去。例如将两条动态旋转取 Y=3.5°、X=-0.3°，Goal 取 Z=-800，原函数得到最终平移约 `(134.272247, -103.520737, -806.542725)`，而非 `(0,0,-800)`。

**相机字段名称已有算法证据。** `SglCamera` 构造路径 `0x1474d18` 读取节点 `+0x5c` 设置块；`0x1474d29/0x1474d34` 为资源 kind=100 的 selector 1／2 绑定两个矩阵。更新将其平移分别传给 `0x1272a60/0x1272b50`，随后 `0x12725e0` 计算 eye-target、归一化、与 up 叉乘及负点积，组成视图矩阵。因此 selector 1 是 eye、selector 2 是 target。设置 `+12/+16/+20/+24` 经参数容器分别进入 FOV／near／far／aspect；`0x1272ce0 → 0x12724c0` 使用 `1/tan(FOV/2)`，X 缩放再除 aspect，确认这里是垂直 FOV。负 aspect 保留默认相机宽高比；本文件为 -1，播放器按自己的 16:9 视口明确提供宽高比。

## 已落盘接口与剩余界限

生产文件为 [game-stage-program.ts](../src/backend/game-stage-program.ts) 与 [stage-program.ts](../src/core/stage-program.ts)：

- `parseGameStageProgram(bytes, sourceName)` 解码 AFNC 节点、资源引用、状态及命令；POF0、块边界、数量、缺失重定位和环均有检查。未知命令保留类型、头及描述头，附诊断；不是完整未知 payload 的可逆序列化器。
- `createStageModelSampler(program, 13, seed?)(internalTime)` 执行已确认的 yellowring 子集：每 900 单位重建状态，重新从绑定的十个动作中随机选片，速度 1，局部 Goal 在 800 单位抵达 Z=-1600；父级摆动按全场时间连续运行。返回 `clipResource/clipFrame/cycle/localTime`、`worldMatrix`（**column-major 4×4、长度 16**）、`camera` 及诊断。seek、重播不依赖之前采样顺序。当前资源表 1…10 对应 clips 数组 0…9；这个减一映射只对已核查的 yellowring 资源成立。
- `getStageCamera(program, 25)` 返回已确认的静态 eye／target、up、`verticalFovDegrees`、near／far／aspect。动态或有额外父级命令的相机拒绝执行，不据其他状态编号猜用途。

测试见 [stage-program.test.ts](../tests/stage-program.test.ts) 与 [stage-native-math.json](../tests/fixtures/stage-native-math.json)。不依赖游戏安装的合成数据与数值回归可以直接运行；真实 AFB 两项测试在本机通过，无安装时明确跳过。

尚未宣称整场像素等价：应用的 60 或 30 内部单位／秒是明确的预览设置；原游戏与歌曲秒数的换算来源未确认。状态切换在原引擎具体更新步上的执行相位未复现，连续时间采样在边界可能相差一次更新。独立种子复用了原 PRNG 算法，但全场其他随机消费者及原始种子未复现。`MomMaterial/MomUvScroll` 保留而未执行，其他舞台节点、外部矩阵、灯光和粒子也未纳入这个子集。
